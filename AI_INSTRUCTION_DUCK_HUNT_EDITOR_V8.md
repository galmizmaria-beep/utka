# «Меткий ответ» — техническое задание V8

## 1. Статус документа

Этот документ продолжает требования V1–V7 и имеет наивысший приоритет при противоречиях. Его задача — исправить экспорт в Genially, расширить локализацию, добавить уровни сложности и сделать каждый раунд самостоятельной редактируемой сущностью.

Требуется изменить существующий редактор и игровой runtime. Нельзя ограничиваться статичным макетом или демонстрационными кнопками.

## 2. Главные задачи V8

Необходимо реализовать:

1. Надёжный запуск готовой игры внутри Genially.
2. Полный перевод системного интерфейса игры при выборе языка.
3. Автоматический перевод вопросов и ответов учителя.
4. Три уровня сложности: лёгкий, средний и сложный.
5. Выбор сложности учеником на титульном экране.
6. Независимые настройки каждого раунда.
7. Собственное количество заданий в каждом раунде.
8. Визуальное выделение выбранного раунда в редакторе.
9. Одинаковую игровую логику в Preview, HTML и Genially.

## 3. Критическое исправление Genially

### 3.1. Причина проблемы

Genially может блокировать:

- iframe с большим `data:text/html;base64`;
- JavaScript внутри `srcdoc`;
- слишком длинные атрибуты HTML;
- автоматический запуск `AudioContext`;
- локальные пути и Blob URL;
- код, размер которого превышает ограничение поля вставки.

Поэтому Base64-код нельзя считать основным и гарантированно совместимым способом публикации.

### 3.2. Основной способ публикации

Основным режимом Genially должен стать короткий iframe с публичным HTTPS-адресом игры:

```html
<div style="position:relative;width:100%;max-width:100%;aspect-ratio:16/9;overflow:hidden">
  <iframe
    src="https://PUBLIC-DOMAIN/game.html"
    title="Меткий ответ"
    style="position:absolute;inset:0;width:100%;height:100%;border:0"
    allow="autoplay; fullscreen"
    allowfullscreen>
  </iframe>
</div>
```

### 3.3. Публикация готовой игры

Редактор должен иметь действие «Опубликовать для Genially».

Возможные реализации:

- публикация автономного `game.html` через GitHub Pages;
- публикация через другой статический HTTPS-хостинг;
- загрузка заранее скачанного HTML учителем на собственный HTTPS-сервер.

После публикации редактор должен:

1. Получить публичный URL готовой игры.
2. Проверить, что URL начинается с `https://`.
3. Открыть URL в тестовом iframe.
4. Дождаться события готовности runtime.
5. Скопировать короткий код iframe.

Нельзя подставлять URL страницы редактора вместо URL автономной игры.

### 3.4. Протокол готовности iframe

Автономная игра после инициализации отправляет родительскому окну:

```js
window.parent.postMessage(
  { type: "METKIY_OTVET_READY", version: 8 },
  "*"
);
```

Редактор при проверке публикации ожидает это сообщение. Если сообщение не получено за 10 секунд, показывается понятная ошибка:

> Игра не запустилась по указанному адресу. Проверьте публикацию HTML и доступ по HTTPS.

### 3.5. Требования к автономной игре

Автономный HTML должен содержать:

- ProjectConfig V8;
- единый GameRuntime;
- CSS игры;
- локализацию;
- задания всех раундов;
- изображения;
- пользовательские звуки;
- LaTeX-рендерер;
- помощника;
- уровни сложности;
- HUD;
- таймер;
- финальные экраны.

Запрещены ссылки на:

- `localhost`;
- `127.0.0.1`;
- `blob:`;
- `/src/`;
- `node_modules`;
- файлы компьютера пользователя.

### 3.6. Масштабирование

Внутри iframe:

```css
html,
body {
  width: 100%;
  height: 100%;
  margin: 0;
  overflow: hidden;
}

.game-stage {
  width: 100%;
  height: 100%;
  aspect-ratio: 16 / 9;
  max-width: none;
}
```

Игра должна полностью помещаться в блок Genially без горизонтальной или вертикальной прокрутки.

### 3.7. Разблокировка звука

Звук запускается только после клика ученика по кнопке «Играть».

```js
await audioManager.unlock();
await gameRuntime.start();
```

Ошибка звука не должна останавливать игру.

## 4. Полная локализация игры

### 4.1. Поддерживаемые языки

Минимальный список:

- русский;
- английский;
- испанский;
- немецкий;
- французский;
- итальянский;
- казахский.

Архитектура должна позволять добавлять новые языки без изменения игрового runtime.

### 4.2. Системные строки

При смене языка автоматически переводятся:

- «Играть»;
- «Пропустить»;
- «Раунд»;
- «Счёт»;
- «Жизни»;
- «Время»;
- «Проверить»;
- «Продолжить»;
- «Попробовать снова»;
- «Играть снова»;
- «Правильно»;
- «Неправильно»;
- «Время закончилось»;
- «Победа»;
- «Поражение»;
- названия типов вопросов;
- названия уровней сложности;
- сообщения об ошибках выбора ответа;
- подсказки заданий на порядок;
- текст устного задания.

### 4.3. Пользовательские формулировки

Нужно различать:

1. Системный текст приложения.
2. Пользовательский учебный контент.

Системный текст переводится через встроенный словарь.

Для пользовательского контента реализуется мультиязычная структура:

```ts
interface LocalizedText {
  sourceLocale: SupportedLocale;
  values: Partial<Record<SupportedLocale, string>>;
}
```

### 4.4. Автоматический перевод заданий

При выборе нового языка редактор предлагает:

- «Перевести автоматически»;
- «Оставить исходный текст»;
- «Ввести перевод вручную».

Автоматически переводятся:

- название игры;
- подзаголовок;
- правила помощника;
- название каждого раунда;
- вопросы;
- варианты ответов;
- сообщения победы, поражения и окончания времени;
- пользовательские надписи кнопок.

Оригинальный текст никогда не удаляется.

### 4.5. Защита LaTeX при переводе

Формулы нельзя отправлять переводчику как обычный текст.

Перед переводом выражения временно заменяются токенами:

```text
Чему равно $\frac{1}{2}$? → Чему равно __MATH_0__?
```

После перевода формула возвращается на место.

Нельзя изменять:

- содержимое `$...$`;
- содержимое `$$...$$`;
- управляющие команды LaTeX;
- числа и математические символы внутри формул.

### 4.6. Редактор переводов

Для каждого пользовательского текста должна быть возможность открыть таблицу переводов:

| Язык | Текст | Статус |
|---|---|---|
| Русский | Исходный вопрос | Оригинал |
| English | Translated question | Автоперевод |
| Español | Pregunta traducida | Изменён вручную |

Учитель может редактировать любой перевод вручную.

### 4.7. Работа без сервиса перевода

Если автоматический сервис перевода недоступен:

- системные строки продолжают переводиться;
- игра не ломается;
- исходный пользовательский текст остаётся видимым;
- редактор показывает предупреждение;
- доступен ручной ввод перевода.

## 5. Уровни сложности

### 5.1. Список уровней

В игру добавляются три уровня:

1. Лёгкий.
2. Средний.
3. Сложный.

### 5.2. Выбор на титульном экране

На титульном экране под описанием игры располагается блок выбора сложности.

```text
Выберите уровень:
[ Лёгкий ] [ Средний ] [ Сложный ]
```

До выбора уровня кнопка «Играть» может быть заблокирована либо используется уровень по умолчанию, заданный учителем.

Выбранная кнопка визуально выделяется. Названия уровней автоматически переводятся.

### 5.3. Конфигурация сложности

```ts
type DifficultyId = "easy" | "medium" | "hard";

interface DifficultyConfig {
  id: DifficultyId;
  enabled: boolean;
  targetSpawnInterval: number;
  targetFlightDuration: number;
  simultaneousTargets: number;
  targetSizeMultiplier: number;
  timerMultiplier: number;
  scoreMultiplier: number;
}
```

### 5.4. Значения по умолчанию

#### Лёгкий

- интервал появления: 3,5 секунды;
- продолжительность полёта: 6 секунд;
- одновременно целей: 1;
- размер цели: 120%;
- время: 130%;
- множитель баллов: 1.

#### Средний

- интервал появления: 2 секунды;
- продолжительность полёта: 4 секунды;
- одновременно целей: 2;
- размер цели: 100%;
- время: 100%;
- множитель баллов: 1,5.

#### Сложный

- интервал появления: 1 секунда;
- продолжительность полёта: 2,5 секунды;
- одновременно целей: 3;
- размер цели: 80%;
- время: 75%;
- множитель баллов: 2.

### 5.5. Настройки учителя

В редакторе создаётся раздел «Уровни сложности».

Для каждого уровня учитель меняет:

- включение уровня;
- подпись;
- цвет кнопки;
- интервал появления целей;
- скорость/длительность движения;
- количество одновременно летящих целей;
- размер цели;
- время;
- множитель баллов.

Учитель может выбрать уровень по умолчанию.

### 5.6. Применение уровня

После выбора ученика GameRuntime создаёт эффективные настройки:

```js
effectiveTargetSize = baseTargetSize * difficulty.targetSizeMultiplier;
effectiveTimer = baseTimer * difficulty.timerMultiplier;
effectiveScore = baseScore * difficulty.scoreMultiplier;
```

Смена уровня не изменяет сохранённые базовые настройки проекта.

## 6. Раунды

### 6.1. Самостоятельная сущность

Каждый раунд хранится отдельно:

```ts
interface RoundConfigV8 {
  id: string;
  order: number;
  enabled: boolean;
  title: LocalizedText;
  introDuration: number;
  introAnimation: string;
  taskCount: number;
  tasks: TaskV8[];
  targetOverrides?: Partial<TargetConfig>;
  timerOverrides?: Partial<TimerConfig>;
  backgroundAssetId?: string | null;
}
```

### 6.2. Вкладки раундов

В редакторе отображается горизонтальный или вертикальный список:

```text
[ Раунд 1 ] [ Раунд 2 ] [ Раунд 3 ] [ + Добавить ]
```

Требования:

- активный раунд выделяется цветом и рамкой;
- отображаются только задания выбранного раунда;
- смена раунда не запускает игру;
- смена раунда не сбрасывает предпросмотр;
- раунд можно добавить;
- раунд можно дублировать;
- раунд можно удалить через окно «Удалить / Оставить»;
- раунды можно менять местами;
- минимум один раунд всегда остаётся.

### 6.3. Количество заданий

Каждый раунд имеет собственное поле «Количество заданий».

Например:

```text
Раунд 1 — 5 заданий
Раунд 2 — 8 заданий
Раунд 3 — 3 задания
```

Количество заданий не является общей настройкой всей игры.

Если учитель указал количество больше числа введённых заданий:

- редактор показывает ошибку;
- запуск теста блокируется;
- экспорт предупреждает о неполной конфигурации.

Если заданий больше указанного количества, в раунде используются первые N заданий либо выбранные учителем задания.

### 6.4. Задания раунда

Внутри каждого раунда сохраняется единое текстовое поле с форматом `|`.

```text
Раунд 1:
2 + 2? | 4* | 5 | 6
Столица Франции? | Париж* | Рим | Берлин

Раунд 2:
[порядок] Расставьте числа | 1 | 2 | 3
[устно] Объясните решение задачи
```

Поддерживаются:

- один правильный ответ;
- несколько правильных ответов;
- устный вопрос;
- расстановка по порядку;
- LaTeX;
- локализованные вопросы и ответы.

### 6.5. Переход между раундами

После выполнения заданий текущего раунда:

1. Все активные цели удаляются.
2. Таймер текущего раунда останавливается.
3. Показывается заставка следующего раунда.
4. Применяются фон и переопределения следующего раунда.
5. Заставка полностью исчезает.
6. Запускаются цели следующего раунда.

Цели не должны двигаться под заставкой раунда.

### 6.6. HUD

HUD показывает реальный прогресс:

```text
Раунд 2 / 3   Задание 4 / 8   ❤❤❤   ★ 240   ⏱ 00:48
```

Номер раунда и количество заданий берутся из активного `RoundConfigV8`.

## 8. Миграция старых проектов

Нужно поддержать V1–V7 → V8.

Правила миграции:

- старый общий список заданий переносится в «Раунд 1»;
- прежнее количество раундов создаёт соответствующее количество `RoundConfigV8`;
- при отсутствии отдельных заданий дополнительные раунды получают копию списка либо остаются с предупреждением;
- старые настройки цели становятся базовыми;
- создаются три стандартных уровня сложности;
- текущий язык становится `sourceLocale`;
- старые изображения и звуки сохраняются;
- неизвестные поля не должны повреждать загрузку проекта.

## 9. Единый runtime

Preview, автономный HTML и Genially используют один и тот же GameRuntime.

Запрещено:

- создавать отдельную упрощённую игру для Genially;
- иметь разную логику раундов в Preview и HTML;
- иметь разные парсеры заданий;
- пропускать локализацию в экспорте;
- заменять пользовательские изображения заглушками;
- отключать звук вместо исправления разблокировки.

## 10. Проверки

### 10.1. Genially

- скачать автономный HTML;
- опубликовать его по HTTPS;
- открыть URL напрямую;
- дождаться `METKIY_OTVET_READY`;
- вставить короткий iframe в Genially;
- проверить титул, звук, помощника, уровни, раунды, задания и финальные экраны;
- проверить размеры на мобильном и настольном слайде.

### 10.2. Локализация

- переключить каждый язык;
- проверить все системные кнопки;
- перевести название, правила, вопрос и ответы;
- проверить сохранность LaTeX;
- изменить автоперевод вручную;
- экспортировать и повторить проверку.

### 10.3. Сложность

- выбрать каждый уровень на титуле;
- сравнить интервал появления целей;
- сравнить скорость;
- сравнить число целей;
- сравнить размер цели;
- сравнить таймер и баллы.

### 10.4. Раунды

- создать минимум три раунда;
- задать разное количество заданий;
- проверить визуальное выделение вкладок;
- пройти игру полностью;
- убедиться, что задания не смешиваются;
- проверить заставку перед каждым раундом;
- проверить HUD;
- проверить экспорт HTML и Genially.

## 11. Definition of Done

- готовая игра отображается и запускается в Genially через HTTPS iframe;
- iframe полностью помещается в блок 16:9;
- системные строки переводятся при смене языка;
- пользовательские вопросы и ответы имеют переводы;
- LaTeX не повреждается переводом;
- на титульном экране доступны три уровня сложности;
- уровни отличаются частотой, скоростью, количеством и размером целей;
- каждый раунд выделен отдельной вкладкой;
- каждый раунд имеет собственное количество заданий;
- задания разных раундов не смешиваются;
- цели запускаются только после исчезновения заставки раунда;
- Preview, HTML и Genially используют одинаковую конфигурацию и runtime;
- старые проекты мигрируют в V8;
- автоматические smoke- и E2E-тесты проходят без ошибок.

## 12. Финальная инструкция исполнителю

Не ограничиваться созданием новых элементов интерфейса. Каждая настройка должна:

1. Сохраняться в ProjectConfig V8.
2. Сразу применяться в выбранном экране предпросмотра.
3. Работать в полноценном тестировании.
4. Переноситься в автономный HTML.
5. Работать в игре, открытой через HTTPS iframe в Genially.
6. Восстанавливаться после загрузки JSON-проекта.

После реализации перечислить изменённые файлы, результаты миграции, локализации, тестов сложности, тестов раундов и проверки Genially.
