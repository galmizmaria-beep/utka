# Техническое задание V3: расширение редактора и игры «Меткий ответ»

> Этот документ дополняет `AI_INSTRUCTION_DUCK_HUNT_EDITOR.md` и `AI_INSTRUCTION_DUCK_HUNT_EDITOR_V2.md`. При противоречиях требования V3 имеют наивысший приоритет. Задача ИИ-разработчика — доработать существующее приложение, а не создавать статичный макет.

## 1. Цель обновления

Расширить редактор и игровой runtime следующими возможностями:

- отдельный фон внутри рамки титульной карточки;
- значительно увеличить библиотеки целей и помощников;
- расширить библиотеку эффектов попадания;
- привязывать эффект к фактической точке попадания;
- расширить варианты отображения жизней;
- добавить игровой таймер;
- создать редактируемые экраны тайм-аута, победы и поражения;
- разрешить загрузку своих изображений для итоговых экранов;
- разрешить изменение дизайна таймера;
- убрать из шапки редактора поле «Название проекта — Моя учебная игра»;
- разрешить загрузку своего звука для каждого игрового события;
- упростить создание заданий до одного универсального текстового поля с разделителем `|`;
- заменить системные подтверждения удаления на собственное окно с кнопками «Удалить» и «Оставить»;
- исправить звуки и эффекты в коде для Genially.

Все новые настройки должны:

1. сразу отражаться в предпросмотре без мигания;
2. сохраняться в JSON проекта;
3. восстанавливаться после загрузки проекта;
4. попадать в автономный HTML;
5. одинаково работать в редакторе, скачанном HTML и Genially.

```ts

```

Обязательны миграции:

- V1 → V3;

- старые пользовательские изображения и звуки сохраняются;
- отсутствующие параметры получают безопасные значения по умолчанию.

## 3. Удаление названия проекта из шапки

Полностью убрать из верхней панели редактора:

- подпись «Название проекта»;
- поле со значением «Моя учебная игра».

Название игры редактируется только в разделе «Титульный экран» в поле «Название игры».

Для имени скачиваемого JSON/HTML использовать:

1. название титульного экрана, если оно заполнено;
2. значение `metkiy-otvet`, если название пустое.

Удаление поля из шапки не должно удалять название из титульного экрана, HTML `<title>` и итоговых файлов.

## 4. Фон внутри рамки титульного экрана

### 4.1. Два независимых слоя фона

Титульный экран должен иметь два отдельных фона:

1. **Фон всего титульного экрана** — занимает сцену 16:9.
2. **Фон карточки внутри рамки** — заполняет только плашку, на которой находятся название, подзаголовок и кнопка «Играть».

Не путать эти изображения и не использовать одно поле для двух слоёв.

### 4.2. Настройки внутренней плашки

```ts
interface TitleCardBackgroundConfig {

```

В редакторе добавить плашку «Фон внутри рамки»:

Название и кнопка должны оставаться читаемыми на любом изображении. Проверять контраст; при плохом контрасте показывать рекомендацию, но не изменять авторский дизайн автоматически.

### 7.1. Точная позиция попадания

Эффект должен появляться именно в координате выстрела, а не в центре сцены и не обязательно в центре цели.

При клике/касании:

```ts
const stageRect = stage.getBoundingClientRect();
const hitX = pointer.clientX - stageRect.left;
const hitY = pointer.clientY - stageRect.top;
```

Сохранить координаты в игровом событии `TargetHitEvent` и передать их системе частиц.

```ts
interface TargetHitEvent {
  targetId: string;
  x: number;
  y: number;
  normalizedX: number;
  normalizedY: number;
  timestamp: number;
}
```

Использовать координаты относительно сцены. При масштабировании iframe эффект должен оставаться под прицелом. Частицы не должны смещаться из-за положения страницы, прокрутки или CSS transform.

Цель удаляется только после запуска эффекта. Повторное попадание блокируется.

## 13. Новый единый ввод заданий

### 13.1. Главное изменение

В разделе «Задания» убрать сложную форму с отдельным выбором типа, отдельными карточками ответов и отдельными radio/checkbox правильности.

Оставить **одно основное многострочное поле**, в котором учитель вводит вопрос и ответы через прямую палочку `|`.

Каждая строка является одним заданием.

### 13.2. Формат строк

Один правильный ответ:

```text
Столица Франции? | Париж* | Лондон | Рим
```

Звёздочка `*` после варианта означает правильный ответ.

Множественный выбор:

```text
Выберите простые числа | 2* | 3* | 4 | 6
```

Если звёздочкой отмечено больше одного варианта, тип автоматически определяется как множественный выбор.

Расставить по порядку:

```text
[порядок] Расположите числа по возрастанию | 2 | 5 | 9
```

Порядок вариантов в редакторе является правильным порядком. В игре они перемешиваются.

Устный вопрос:

```text
[устно] Объясните, почему меняются времена года
```

LaTeX:

```text
Чему равно $x^2$, если $x=3$? | $9$* | $6$ | $3$
```

### 13.3. Экранирование прямой палочки

Если символ `|` нужен внутри текста, использовать `\|`.

Парсер должен:

- разделять только неэкранированные `|`;
- удалять служебную звёздочку правильности;
- не удалять математические символы;
- поддерживать пустые строки и комментарии, начинающиеся с `#`;
- сообщать номер строки с ошибкой;
- не терять исходный текст учителя.

### 13.4. Интерфейс

Под основным полем показывать:

- живой список распознанных заданий;
- определённый тип каждого задания;
- число ответов;
- правильные ответы;
- отрендерованные формулы;
- ошибки конкретных строк;
- счётчик корректных заданий.

Изменения применять с debounce 150–250 мс. Поле не должно терять курсор или прокрутку.

Добавить кнопку «Пример формата», открывающую краткую памятку, и кнопку «Скопировать шаблон».

### 13.5. Внутренняя модель

Парсер преобразует строки в обычные типизированные задания `TaskV3`. Игровой runtime не должен разбирать текст заново при каждом показе вопроса.

Стабильный ID строки можно получать из сохранённой карты либо создавать при первом парсинге. Для задания на порядок каждый элемент получает отдельный стабильный ID.

## 14. Собственное подтверждение удаления

Не использовать `window.confirm`, `window.prompt`, браузерные предупреждения или окна, содержащие прямую ссылку на GitHub.

При удалении задания, фона, изображения, звука, проекта или другого элемента открывать собственное модальное окно редактора.

Обязательное содержимое:

- заголовок «Удалить изменения?» либо более конкретный заголовок;
- описание удаляемого объекта;
- кнопка «Удалить»;
- кнопка «Оставить».

Поведение:

- «Удалить» выполняет действие;
- «Оставить» закрывает окно без изменений;
- Escape соответствует «Оставить»;
- начальный фокус находится на безопасной кнопке «Оставить»;
- Tab не выходит за пределы диалога;
- после закрытия фокус возвращается к кнопке удаления;
- никакие ссылки на GitHub в диалоге не показываются;
- случайное нажатие за пределами окна не подтверждает удаление.

Для ухода со страницы с несохранёнными изменениями допускается стандартный `beforeunload`, но внутри редактора все удаления используют только собственный диалог.

## 15. Исправление звука в Genially

### 15.1. Причина проблемы

Браузеры блокируют запуск звука до пользовательского жеста, особенно внутри iframe. Нельзя запускать AudioContext при загрузке документа и нельзя считать редакторский AudioContext доступным внутри экспортированного iframe.

### 15.2. Обязательная реализация

Внутри экспортированной игры создать независимый `AudioManager`.

После первого клика по кнопке «Играть»:

1. создать либо возобновить `AudioContext`;
2. вызвать `audioContext.resume()`;
3. декодировать необходимые пользовательские звуки;
4. отметить аудиосистему как разблокированную;
5. только затем запускать вступление и игровой цикл.

Для `<audio>` использовать `playsinline` и не полагаться на autoplay.

Iframe Genially должен получать:

```html
allow="autoplay; fullscreen"
```

Но наличие `allow` не заменяет пользовательский жест.

Если звук не удалось воспроизвести:

- игра продолжает работать;
- ошибка не ломает runtime;
- в консоли только одно понятное предупреждение;
- пользователь может повторно включить звук кнопкой в игре.

## 16. Исправление эффектов в Genially

Эффекты должны использовать координаты внутри `gameStage`, а не `pageX/pageY` и не координаты родительской страницы Genially.

Требования:

- система частиц находится внутри игрового контейнера;
- контейнер имеет `position: absolute; inset: 0; pointer-events: none`;
- координаты вычисляются через `clientX/clientY` и rect сцены;
- учитывать CSS-масштаб iframe;
- эффект не обрезается раньше времени;
- таймер удаления эффекта работает внутри iframe;
- CSS всех 16 эффектов включён в `srcdoc`/HTML;
- пользовательские цвета и размеры сериализуются;
- `prefers-reduced-motion` сокращает эффект, но не удаляет обратную связь полностью.

## 17. Идентичность предпросмотра и Genially

Убрать отдельную упрощённую логику Genially. Предпросмотр, автономный HTML и Genially должны использовать:

- один `GameRuntime`;
- один `AudioManager`;
- один `ParticleEngine`;
- один `TimerController`;
- один parser/render математических формул;
- один набор CSS;
- одну конфигурацию проекта.

При экспорте сериализуется текущий `ProjectConfigV3`, а не вручную выбранное подмножество настроек.

Проверить в Genially:

- встроенные звуки;
- пользовательские звуки;
- старт после клика;
- каждый тип эффекта;
- точную позицию эффекта;
- таймер;
- тайм-аут;
- победу;
- поражение;
- пользовательские изображения;
- мобильное касание.
