# Техническое задание V2: усовершенствование редактора «Меткий ответ»

> Этот документ содержит обязательные исправления и расширения существующего редактора. Он дополняет исходный файл `AI_INSTRUCTION_DUCK_HUNT_EDITOR.md`. Если требования документов расходятся, приоритет имеет эта версия V2.

## 1. Цель обновления

Доработать существующий браузерный редактор учебной игры так, чтобы учитель мог без программирования:

- выбрать язык системного интерфейса игры;
- создавать задания с обычным текстом и математическими формулами LaTeX;
- загружать оптимизированные пользовательские изображения;
- отдельно оформлять титульный экран;
- настраивать шрифты, звуки, помощника, прицел, жизни, цели и траектории;
- сразу тестировать результат в стабильном окне предпросмотра;
- скачивать автономный HTML и получать код для Genially, визуально и функционально идентичный предпросмотру.

Нельзя ограничиваться добавлением декоративных полей. Каждая настройка должна влиять на предпросмотр, сохраняться в проекте и попадать в экспортированную игру.

## 2. Перечень обнаруженных проблем

Исправить следующие недостатки текущей версии:

1. Выбор языка недостаточно заметен или недоступен.
2. После смены языка переводятся не все игровые надписи.
3. Левая панель инструментов обрезается, часть элементов невозможно увидеть.
4. Нет поддержки математической разметки LaTeX.
5. Во вкладке фонов отображается ненужная встроенная библиотека.
6. Пользовательские изображения не оптимизируются перед сохранением и экспортом.
7. Нет включаемого титульного экрана и его подробного оформления.
8. Нет выбора шрифта для всей игры.
9. Нет встроенной библиотеки звуков.
10. Задание «Расставь по порядку» работает неправильно или не завершается.
11. Нет настройки размера и вида прицела.
12. Помощник не рассказывает заданные учителем правила после старта.
13. Нет настройки времени показа и анимации помощника.
14. Нет настройки траекторий, частоты и темпа появления целей.
15. Нет анимации взрыва/исчезновения цели после попадания.
16. Нет системы жизней и настройки их количества.
17. Экспорт для Genially может отличаться от предпросмотра.
18. Внешний вид редактора слишком белый и визуально устаревший.

## 3. Обязательные архитектурные изменения

### 3.1. Единая конфигурация проекта

Расширить единый объект `ProjectConfig`. Не хранить новые настройки только в DOM или отдельных глобальных переменных.

```ts
interface ProjectConfigV2 {
  schemaVersion: 2;
  meta: {
    title: string;
    createdAt: string;
    updatedAt: string;
  };
  locale: SupportedLocale;
  font: GameFontId;
  titleScreen: TitleScreenConfig;
  scene: SceneConfig;
  target: TargetConfig;
  crosshair: CrosshairConfig;
  helper: HelperConfig;
  taskTheme: TaskThemeConfig;
  tasks: Task[];
  rules: RulesConfig;
  audio: AudioConfig;
  assets: Record<string, OptimizedAsset>;
}
```

Предусмотреть миграцию проектов `schemaVersion: 1` в версию 2. Старые проекты должны открываться с безопасными значениями новых параметров по умолчанию.

### 3.2. Один игровой runtime

Предпросмотр, скачанный HTML и версия для Genially должны использовать один и тот же игровой runtime, компоненты и CSS. Запрещено поддерживать отдельную упрощённую реализацию экспортированной игры.

Допускаются только различия оболочки:

- в редакторе runtime находится внутри окна предпросмотра;
- в автономном HTML runtime занимает доступное окно браузера;
- в Genially runtime находится внутри адаптивного iframe 16:9.

## 4. Левая панель инструментов

### 4.1. Устранение обрезания

Левая панель должна быть полностью доступна при любой высоте окна от 600 px:

- высота: `calc(100dvh - var(--header-height))`;
- вертикальная прокрутка: `overflow-y: auto`;
- горизонтальная прокрутка запрещена;
- добавить нижний внутренний отступ минимум 80 px;
- закреплять только заголовок/вкладки, но не всю форму;
- длинные подписи переносятся, а не обрезаются;
- поля не должны выходить за ширину панели;
- аккордеоны корректно увеличивают общую прокручиваемую высоту;
- footer не должен перекрывать последние настройки;
- видимый скроллбар должен соответствовать дизайну редактора.

Проверить панель при разрешениях 1366×768, 1440×900, 1920×1080 и при масштабе браузера 125%, 150% и 200%.

### 5.2. Что переводится автоматически

При выборе языка немедленно и без перезагрузки сцены переводятся все системные элементы игры:

- «Раунд»;

## 6. Поддержка математического языка LaTeX

### 6.1. Где поддерживается LaTeX

Распознавать математические формулы в:

- названии игры;
- тексте правил помощника;
- вопросах;
- вариантах ответов;
- элементах задания «Расставь по порядку»;
- подсказках;
- пояснениях после ответа.

Поддержать разделители:

- inline-формула: `$x^2 + y^2 = z^2$`;
- блочная формула: `$$\frac{-b \pm \sqrt{b^2-4ac}}{2a}$$`;
- дополнительно `\(...\)` и `\[...\]`, если библиотека поддерживает их без конфликтов.

### 6.2. Реализация

Использовать KaTeX либо эквивалентную безопасную библиотеку. Для автономного экспорта CSS, шрифты и runtime формул должны быть включены внутрь сборки, без CDN и интернета.

Требования безопасности:

- обычный пользовательский текст сначала экранировать;
- не разрешать пользовательский HTML;
- включить безопасный режим KaTeX;
- при ошибке формулы не ломать окно задания;
- ошибочную формулу показывать как исходный текст и выводить учителю сообщение рядом с полем.

### 6.3. Интерфейс редактора формул

- рядом с поддерживаемыми полями разместить значок `ƒx` и подсказку с примерами;
- добавить переключатель «Предпросмотр формул»;
- под полем показывать живой отрендеренный результат;
- ввод текста не должен мигать или терять позицию курсора;
- применять debounce 100–200 мс только к рендерингу формулы;
- добавить кнопки-шаблоны: дробь, степень, корень, индекс, сумма, интеграл, система уравнений.

## 7. Пользовательский фон без встроенной базы

### 7.1. Изменение вкладки

Полностью убрать из интерфейса раздела «Фон игры» библиотеку готовых картинок. Во вкладке оставить:

- область drag-and-drop;
- кнопку «Загрузить фон с устройства»;
- миниатюру текущего фона;
- кнопку «Заменить»;
- кнопку «Удалить фон»;
- режим заполнения: `cover` / `contain`;
- положение по X и Y;
- затемнение фона от 0 до 70%;
- размытие от 0 до 12 px;
- fallback-цвет, который отображается без изображения.

При отсутствии фона использовать современный нейтральный градиент, а не пустую белую сцену.

### 7.2. Автоматическое сжатие изображений

Все загружаемые изображения — фон игры, фон титульного экрана, цель и помощник — автоматически оптимизировать **до** сохранения в состоянии проекта:

1. проверить тип и размер файла;
2. декодировать изображение через `createImageBitmap` либо `img.decode()`;
3. изменить размер через canvas/OffscreenCanvas;
4. сохранить оптимизированную версию;
5. сравнить исходный и итоговый размер;
6. показать учителю результат, например «2,8 МБ → 340 КБ»;
7. использовать оптимизированный файл в предпросмотре, JSON и экспорте.

Значения по умолчанию:

- фон: максимум 1920×1080;
- фон титульного экрана: максимум 1920×1080;
- цель: максимум 512×512;
- помощник: максимум 768×768;
- фотографические изображения: WebP quality 0.78–0.84;
- прозрачные изображения: WebP с alpha либо оптимизированный PNG;
- анимированный GIF не сжимать через обычный canvas с потерей кадров; либо сохранить исходник с предупреждением, либо явно отказаться от GIF.

Нельзя увеличивать маленькие изображения. Если оптимизированный файл оказался больше исходного, оставить исходный. Для браузеров без WebP использовать JPEG/PNG fallback.

## 8. Титульный экран

### 8.1. Включение и выключение

Добавить checkbox «Показывать титульный экран».

- checkbox включён — в предпросмотре показывается титульный экран и доступны его настройки;
- checkbox выключен — предпросмотр переходит к редактированию основной игровой сцены;
- в экспортированной игре при выключенной опции сразу начинается вступление помощника либо показывается минимальная кнопка запуска, необходимая браузеру для разблокировки звука;
- переключение не удаляет настройки титульного экрана;
- повторное включение восстанавливает прежнее оформление.

Добавить явные кнопки предпросмотра «Титульный экран» и «Игровая сцена», чтобы учитель мог быстро переключаться между ними даже при включённом титульном экране.

## 11. Исправление задания «Расставь по порядку»

### 11.1. Требуемое поведение

- учитель создаёт минимум два элемента и задаёт их правильный порядок;
- в начале задания элементы перемешиваются Fisher–Yates;
- перемешанный порядок не должен случайно совпадать с правильным при количестве элементов больше одного; при совпадении перемешать повторно;
- ученик меняет порядок drag-and-drop;
- обязательно дублировать управление кнопками «Вверх» и «Вниз»;
- поддержать клавиатуру;
- после каждого перемещения обновлять фактический массив порядка;
- кнопка «Проверить» сравнивает стабильные ID элементов, а не их текст и не текущие DOM-индексы;
- повторяющиеся тексты элементов не должны ломать проверку;
- после проверки список блокируется;
- верный порядок подсвечивается зелёным;
- при ошибке элементы, стоящие не на своих местах, отмечаются красным, затем по настройке показывается правильный порядок.

### 11.2. Модель данных

```ts
interface OrderItem {
  id: string;
  content: string;
  correctPosition: number;
}
```

### 11.3. Обязательные тесты

- 2, 5 и 10 элементов;
- одинаковый текст у двух элементов;
- перемещение первого элемента вниз;
- перемещение последнего вверх;
- drag-and-drop;
- клавиатурные кнопки;
- повторное прохождение задания;
- экспортированный HTML и Genially.

При изменении варианта и размера прицел сразу обновляется в предпросмотре. Область попадания должна быть связана с положением центра прицела, а не с его визуальным размером.

## 13. Помощник и правила игры

### 13.1. Сценарий после старта

После нажатия кнопки «Играть»:

1. титульный экран исчезает;
2. игровая сцена становится видимой;
3. помощник появляется с выбранной анимацией входа;
4. рядом появляется речевая плашка с правилами учителя;
5. цели и игровой таймер пока не запускаются;
6. правила отображаются заданное время;
7. помощник уходит с выбранной анимацией выхода;
8. только после завершения выхода начинается раунд и появляются цели.

Добавить опциональную кнопку «Пропустить правила». При её нажатии корректно завершить вступление, очистить таймер и запустить игру только один раз.

### 13.2. Настройки помощника

- выбор встроенного помощника;
- загрузка и сжатие своего изображения;
- многострочное поле «Текст правил»;
- поддержка LaTeX в тексте правил;
- время показа от 1 до 30 секунд;
- размер помощника;
- положение слева/по центру/справа;
- размер речевой плашки;
- включение кнопки «Пропустить»;
- анимация входа;
- анимация выхода.

Анимации входа:

- плавное появление;
- снизу вверх;
- слева;
- справа;
- увеличение;
- подпрыгивание;
- без анимации.

Анимации выхода:

- плавное исчезновение;
- вниз;
- влево;
- вправо;
- уменьшение;
- без анимации.

Использовать события завершения анимации с запасным таймером, а не набор несогласованных `setTimeout`. Учитывать `prefers-reduced-motion`.

## 14. Цели, траектории и частота появления

### 14.1. Настройки траекторий

Добавить список:

- слева направо;
- справа налево;
- снизу вверх;
- диагональ вверх;
- диагональ вниз;
- дуга;
- синусоида;
- зигзаг;
- круг/петля;
- случайная из выбранных.

Учитель может отметить несколько разрешённых траекторий. Для каждой новой цели выбирать одну случайно либо использовать заданную последовательность.

### 14.2. Частота и сложность

Настройки:

- задержка до первой цели;
- интервал появления в секундах;
- случайный разброс интервала;
- максимальное число целей одновременно;
- скорость полёта;
- длительность нахождения в сцене;
- направление;
- размер цели;
- ускорение по раундам;
- безопасная зона, исключающая HUD и края.

Интервалы и анимации должны корректно останавливаться при паузе, открытом задании и скрытой вкладке браузера. После продолжения нельзя создавать дубликаты таймеров.

## 15. Попадание и эффект взрыва

После выстрела в цель:

1. немедленно блокировать повторное попадание;
2. остановить её движение в точке попадания;
3. проиграть выбранный звук;
4. запустить эффект исчезновения/взрыва;
5. после завершения эффекта удалить цель;
6. открыть связанное задание;

Взрыв должен быть мультяшным и ненасильственным: звёзды, конфетти, облачко, световая вспышка или частицы. Не использовать кровь или реалистичное повреждение животных.

Список эффектов:

- звёздная вспышка;
- облачко;
- конфетти;
- пиксельный взрыв;
- волшебные искры;
- растворение;
- без эффекта.

Настроить размер и длительность эффекта. Реализовать через CSS/canvas без внешнего сетевого запроса. Эффект также должен работать в автономном HTML и Genially.

## 16. Жизни

### 16.1. Настройки

- включить/выключить систему жизней;
- количество жизней от 1 до 20;
- выбрать вид индикатора;
- определить события потери жизни;
- определить поведение при нуле жизней.

События потери жизни на выбор:

- промах по сцене;
- цель улетела;
- неправильный ответ;
- истекло время ответа.

### 16.2. Виды индикатора

- сердца;
- звёзды;
- щиты;
- батарейки;
- попытки в виде чисел;
- пользовательский значок.

HUD показывает текущие и максимальные жизни. При потере жизни проигрываются короткая анимация и звук. При нуле жизней:

- поставить игру на паузу;
- показать экран «Попытки закончились»;
- вывести итоговый счёт;
- дать кнопку «Начать заново»;
- не позволять отрицательное количество жизней.

## 17. Современный дизайн редактора

Отказаться от преимущественно белого интерфейса.

Рекомендуемая концепция:

- основной фон редактора: тёмно-синий, графитовый или мягкий цветной градиент;
- панели: полупрозрачные тёмные поверхности с `backdrop-filter`, но с надёжным fallback;
- карточки настроек: разные уровни поверхности, тонкая светлая рамка;
- акцент: фиолетовый/бирюзовый либо настраиваемый;
- текст: светлый с контрастом WCAG AA;
- выбранные элементы: цветная рамка и галочка;
- цветовые поля сопровождаются текстовым значением;
- красивые, но умеренные тени и свечение;
- единые токены цвета, радиусов и анимаций;
- никаких мигающих градиентов и тяжёлых фоновых видео.

Предусмотреть светлую и тёмную тему редактора, но тёмная современная тема может быть основной. Тема редактора не влияет на оформление экспортированной игры.

## 18. Идентичный экспорт HTML и Genially

### 18.1. Главный принцип

Состояние игры, CSS, словари, шрифты, LaTeX-runtime, звуки и оптимизированные изображения сериализуются из того же `ProjectConfigV2`, который использует предпросмотр.

Запрещено:

- заменять пользовательский фон градиентом только в экспорте;
- удалять помощника или его правила;
- упрощать типы заданий;
- менять шрифт;
- игнорировать титульный экран;
- использовать другие размеры прицела;
- исключать жизни, звуки или эффекты;
- поддерживать для экспорта отдельную устаревшую копию игровой логики.

### 18.2. Genially

Поддержать два режима:

1. **Рекомендуемый:** iframe с публичной HTTPS-ссылкой на скачанную/опубликованную игру.
2. **Встроенный:** iframe `srcdoc`, если итоговый размер допускается Genially.

Код должен содержать адаптивный контейнер 16:9:

```html
<div style="position:relative;width:100%;padding-top:56.25%;overflow:hidden">
  <iframe
    src="PUBLIC_GAME_URL"
    title="Учебная игра"
    style="position:absolute;inset:0;width:100%;height:100%;border:0"
    allow="fullscreen; autoplay"
    loading="lazy">
  </iframe>
</div>
```

Для `srcdoc`:

- правильно экранировать `&`, кавычки и закрывающий `script`;
- не обрезать большие строки data URL;
- заранее показывать размер кода;
- предупредить при превышении безопасного лимита;
- предложить вариант с публичным URL;
- проверить работу звука после пользовательского клика;
- не использовать `data:` URL как единственный способ.

### 18.3. Проверка визуальной идентичности

Создать автоматические скриншоты одинаковых состояний:

- титульный экран;
- появление помощника;
- игровая сцена;
- формула в вопросе;
- правильный ответ;
- неправильный ответ;
- задание на порядок;
- экран без жизней;
- финальный экран.

Сравнивать предпросмотр, автономный HTML и Genially-iframe. Допустимое визуальное различие — только масштабирование при сохранении пропорций.

## 20. Обновлённые критерии приёмки

### 20.1. Язык

- выпадающий список виден без поиска по интерфейсу;
- каждый язык меняет все системные элементы;
- пользовательский контент сохраняется;
- смена языка не перезапускает предпросмотр.

### 20.2. Панель

- на экране 1366×768 доступна прокрутка до последней настройки;
- ни одно поле не перекрывается footer;
- при 200% масштабе ничего не становится недоступным.

### 20.3. LaTeX

- `$x^2$`, дробь, корень и блочная формула отображаются корректно;
- ошибочный LaTeX не ломает игру;
- формулы работают офлайн и в Genially.

### 20.4. Фоны и оптимизация

- во вкладке нет библиотеки готовых фонов;
- доступны загрузка, замена и удаление;
- загруженный фон сжимается;
- показан исходный и итоговый размер;
- оптимизированный фон одинаков в предпросмотре и экспорте.

### 20.5. Титульный экран

- checkbox включает и выключает титульный экран;
- настройки не теряются после выключения;
- редактируются фон, размер названия, кнопка, рамка и свечение;
- результат сразу виден;
- экспорт полностью совпадает.

### 20.6. Игровая механика

- выбранный шрифт применяется ко всей игре;
- звуки можно выбрать и прослушать;
- задание на порядок корректно проверяет ID;
- размер/вид прицела меняется;
- помощник рассказывает авторские правила заданное время;
- вход и выход помощника анимированы;
- цели следуют выбранным траекториям и интервалам;
- после попадания проигрывается эффект и открывается ровно одно задание;
- жизни уменьшаются только по выбранным правилам;
- при нуле жизней игра корректно завершается.

### 20.7. Экспорт

- автономный HTML работает без интернета;
- Genially отображает ту же игру;
- работают титульный экран, шрифт, LaTeX, помощник, звуки, траектории, прицел, взрыв, жизни и все задания;
- нет ссылок на localhost;
- пользовательские ассеты включены в экспорт;
- код не содержит неэкранированных пользовательских данных.
